# Local AI Desktop — локальный чат с LLM и Coding Agent для Linux

[English](README.md) · [Русский](README.ru.md)

Local AI Desktop — экспериментальное AI-приложение для Linux: общайтесь с локальными LLM и поручайте задачи по коду AI Agent. Инференс GGUF-моделей выполняется на вашем компьютере через llama.cpp; интерфейс построен на Electron, а runtime Agent — на Rust.

**Скачать:** Linux x86_64 `.deb` версии **v0.1.0 — Experimental Alpha (Pre-release)** доступен на странице [GitHub Releases](https://github.com/Kushch-Yaroslav/local-ai-desktop/releases). Инструкции по установке и требования к внешнему `llama-server` и GGUF-файлам моделей описаны в [руководстве по началу работы](docs/ru/GETTING_STARTED.md).

![Главный интерфейс Local AI Desktop](docs/img/interface/1-e.png)

Используйте **Chat** для повседневных вопросов, а **Agent** — для исследования проекта и задач по разработке. Можно выбрать до двух проектов, ссылаться на файлы через `@`, управлять контекстом, прикладывать документы и изображения, а также включать веб-поиск только для чтения. Для разового доступа к другой папке можно указать абсолютный путь в сообщении: допустимый путь добавит отфильтрованную область файлового доступа Agent, но не станет выбранным проектом и не получит подсказки `@`. Инструменты Agent могут изучать файлы и состояние Git, предлагать изменения и запускать команды с учётом политик scope и подтверждений.

## Рекомендуемые настройки

- **Модель:** для начала попробуйте **Qwen3.8-27B Q4_K_M**. Это основная модель автора для разработки и испытаний, но не универсально лучший выбор.
- **Контекст:** при сложной работе Agent большое окно может вместить больше истории диалога, исходного кода и результатов инструментов. Это помогает реже повторять исследование и запускать компакцию, но не увеличивает скорость генерации токенов. Большой контекст требует больше RAM/VRAM и может увеличить время обработки запроса. Выбирайте наибольший размер, который остаётся стабильным на вашем оборудовании и для вашей задачи. **Find Maximum Context** измеряет конфигурацию ограниченным поиском; подробности — в [руководстве пользователя](docs/ru/USER_GUIDE.md#find-maximum-context).
- **Рассуждения:** начните с умеренных Thinking / Reasoning effort, если модель их поддерживает, и стратегии Agent **Fast** для обычных задач. Thinking управляет особенностями рассуждений самой модели, а Fast/Deep — отдельной стратегией выполнения Agent. Повышайте настройки, когда этого требует задача; максимальная глубина нужна не всегда.

> **О Qwen3.8 и xHigh:** по наблюдениям автора, Qwen3.8-27B с включённым Thinking и уровнем xHigh может рассуждать очень долго; некоторые сложные задачи занимали около часа. Это наблюдение, а не бенчмарк и не ожидаемая длительность каждого запроса. Долгое рассуждение само по себе не означает, что приложение зависло, но следите за прогрессом, инструментами и статусом runtime. xHigh не гарантирует лучшего ответа. Для обычных запросов используйте меньшую или среднюю глубину. [Подробнее](docs/ru/USER_GUIDE.md#qwen38-xhigh).

## Модели и ограничения

Разработка приложения и Agent в первую очередь опиралась на продолжительные практические испытания Qwen3.8-27B. Базовый текстовый чат успешно работал и с другими поддерживаемыми моделями до появления Rich Responses, но это не значит, что каждую модель повторно проверили после последних изменений.

Надёжность Agent зависит от возможностей модели, совместимости вызовов инструментов, шаблона запроса, настроек runtime и того, насколько приложение оптимизировали для этой модели. Rich Responses появились позже: интерфейс отображает графики, KPI-карточки, таблицы, Mermaid-диаграммы и галереи изображений, но автор не проверял все форматы на каждой модели из списка. Поддержка отображения не гарантирует, что модель создаст корректные структурированные данные. Скорость генерации не измеряет надёжность Agent или качество рассуждений. См. [наблюдения по моделям](docs/ru/MODELS.md) и [описание возможностей](docs/ru/FEATURES.md).

Agent не является полностью изолированной средой: изменения файлов и подтверждённые команды терминала могут затронуть реальные данные. Используйте Git и резервные копии. Локальные модели и веб-контент также могут содержать ошибки или вредоносные инструкции.

## Требования и быстрый старт

**Проверено:** Пакет Local AI Desktop v0.1.0 для Linux amd64 `.deb` успешно установлен и прошёл smoke-test первого запуска на компьютере разработчика с Ubuntu 24.04 x86_64. После исправлений настройки и интерфейса установленное приложение повторно проверялось с новыми изолированными профилями XDG для конфигурации, данных и кэша. Финальная проверка подтвердила установку и запуск приложения, первоначальную настройку, выбор и проверку исполняемого файла `llama-server`, выбор модели и успешный запуск приложения.

**Не проверено:** установка на полностью чистую операционную систему, другие дистрибутивы Linux, другие конфигурации оборудования и общая совместимость. Для работы нужны совместимый `llama-server` и локальные веса GGUF; пакет их не содержит. Если модель не помещается в VRAM, настроенное распределение слоёв между GPU и CPU/RAM может позволить её запустить с меньшей скоростью. Полное исчерпание памяти может привести к ошибке модели или runtime; автоматическое восстановление не гарантируется.

Компьютер автора для разработки и испытаний: NVIDIA RTX 3090 (24 ГБ VRAM), AMD Ryzen 7 5700X3D и 64 ГБ DDR4, Linux с llama.cpp. Это не минимальные требования.

## Статус проекта

Local AI Desktop — мой личный проект, который я активно развиваю, использую и проверяю на своём компьютере. Основные сценарии работают в моей тестовой конфигурации; главная модель разработки и испытаний — Qwen3.8-27B. Другие модели я тоже запускал, но проверял менее широко. Совместимость и стабильность на других моделях, конфигурациях оборудования и дистрибутивах Linux ещё требуют более широкого тестирования, поэтому возможны ошибки и неожиданное поведение. Некоторые новые возможности, особенно Rich Responses на разных моделях, нужно проверять дальше. Буду рад отзывам.

Нашли ошибку или хотите предложить улучшение? Создайте обращение в [GitHub Issues](https://github.com/Kushch-Yaroslav/local-ai-desktop/issues).

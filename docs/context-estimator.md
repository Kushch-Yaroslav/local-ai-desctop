# Runtime Max Context discovery

The llama.cpp **Найти Max Context** action performs bounded, explicit discovery for the selected model. It requires a live Local AI Desktop launcher (manual or foreign servers are not switched), refuses to run during generation, starts a 16K probe for each of F16 and Q8_0 target/draft KV with GPU KV offload, checks `/health`, verifies the server-reported context and actual cache types in startup logs, and performs a short completion request that must return assistant content. It projects from each probe, applies an additional 20% context reduction, and then starts the exact candidate context for another health/cache-log check and real inference. If that candidate fails or does not leave the configured minimum RAM/VRAM reserves, discovery makes at most one lower 8K retry. Only the exact context that passed this second launch/inference check is offered, with its measured post-inference headroom. The exact prior runtime is restored before returning. A failed or unverified mode is reported as unsupported and is not offered. RAM-placement candidates are not currently probed or offered.

For each successful probe, `src/main/services/context-estimate.ts` accepts only allocation evidence for the matching model path, live context, active cache precision, and KV placement. It accounts for target/draft weights, KV, compute/output, recurrent state, projector, sequence slots, current free RAM/VRAM, and the model's configured and GGUF train-context limits. It projects beyond the 16K probe using the measured per-token KV allocations, adds a 25% KV projection margin, reserves 10 GiB of system RAM and 3 GiB of device memory, and rounds down to a 4K boundary. These values are derived from runtime logs and live memory snapshots; no Qwen-specific context results are embedded in the code.

The renderer receives separate `(contextWindow, kvCacheType, kvOffload)` options for each validated mode. Selecting one sends the context and cache configuration atomically through the launcher transaction and persists the choice on the conversation only after the launcher confirms the model, context, cache precision, and offload arguments. The launcher confirms target and draft cache types from llama.cpp's effective startup log and restores the prior settings on failure. A discovered option expires after five minutes; selection also resamples the current runtime and rejects it if reconstructed free-memory baselines have shifted by more than 2 GiB host or 512 MiB device. The reported value is the largest candidate in the bounded discovery procedure that passed its exact-context check, not an experimentally proven absolute hardware maximum.

The reserve, 25% KV projection margin, and 20% candidate reduction are conservative policy, not a guarantee against concurrent external memory use or runtime behavior that scales non-linearly with context. An applied setting is still subject to launcher startup confirmation and rollback. If allocation categories, trained context, cache type, placement, or memory snapshots are incomplete or stale, no Max Context option is produced. Ollama exposes observed context only because it does not report the KV allocations needed for this projection.

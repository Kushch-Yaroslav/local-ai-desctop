## Платформа и состояние пакета

**Проверено:** Пакет Local AI Desktop v0.1.0 для Linux amd64 `.deb` успешно установлен и прошёл smoke-test первого запуска на компьютере разработчика с Ubuntu 24.04 x86_64. После исправлений настройки и интерфейса установленное приложение повторно проверялось с новыми изолированными профилями XDG для конфигурации, данных и кэша. Финальная проверка подтвердила установку и запуск приложения, первоначальную настройку, выбор и проверку исполняемого файла `llama-server`, выбор модели и успешный запуск приложения.

**Не проверено:** установка на полностью чистую операционную систему, другие дистрибутивы Linux, другие конфигурации оборудования и общая совместимость. Пакет включает Electron и Rust runtime Agent, но не содержит `llama-server` и веса моделей. В репозитории доступна сборка пакета командой `npm run package:linux`.

Приложение ориентировано на Linux. Текущая цель упаковки — Debian-подобная система x64. Другие дистрибутивы, ARM, сочетания драйверов GPU и окружения рабочего стола требуют отдельной проверки. Компьютер автора для разработки и испытаний — RTX 3090 с 24 ГБ VRAM, Ryzen 7 5700X3D и 64 ГБ DDR4; это не минимальные требования.

## Установка опубликованного `.deb`

Скачайте Linux x86_64 `.deb` версии **v0.1.0 — Experimental Alpha (Pre-release)** со страницы [GitHub Releases](https://github.com/Kushch-Yaroslav/local-ai-desktop/releases) и установите в Ubuntu командой:

```bash
sudo apt install ./local-ai-desktop_0.1.0_amd64.deb
```

Установка и smoke-test первого запуска выполнены на компьютере разработчика с Ubuntu 24.04 x86_64; полностью чистая операционная система и другие дистрибутивы Linux не проверялись.

## Подготовка llama.cpp и моделей GGUF

Установите или соберите llama.cpp с совместимой версией `llama-server`. Пакет приложения не содержит сервер или веса моделей. Возможности runtime зависят от сборки llama.cpp; нужна версия с поддержкой архитектуры модели, GPU backend, projector и выбранного режима MTP, если он используется.

Откройте **Settings → Models and runtime**. В поле **Путь к llama-server или папке с ним** укажите исполняемый файл или содержащую его папку, в том числе родительскую папку вложенной сборки llama.cpp. Кнопки выбора позволяют указать файл или папку. Приложение проверит файл или выполнит ограниченный поиск в указанной папке; если найдено несколько файлов, выберите один. Проверьте найденный путь и сохраните настройки перед запуском. Ранее сохранённые пути к исполняемому файлу остаются совместимыми. Укажите каталог хранения моделей GGUF. Добавьте модель, выбрав файл GGUF и, если нужен vision, соответствующий projector. Пути задаёт пользователь. Сохраните настройки, выберите модель в панели и запустите её.

![Настройки llama-server, каталога моделей, GPU-слоёв и веб-провайдера](../img/settings.png)

Значение CPU/GPU layers по умолчанию — `999`: приложение просит llama.cpp передать GPU максимально возможное число слоёв модели. Значение `0` просит выполнять слои модели на CPU. Это запросы backend; фактическое размещение зависит от модели, сборки и оборудования.

Если вся модель не помещается в VRAM, можно настроить частичное распределение: часть слоёв работает на GPU, остальные — на CPU, а данные модели занимают системную RAM. Так можно запустить более крупную модель, обычно ценой заметного снижения скорости. Это намеренная конфигурация и она отличается от ошибки нехватки памяти.

Автор не проверял полное исчерпание VRAM/RAM; автоматическое восстановление приложения в таком случае не подтверждено. Возможны ошибка загрузки модели, выделения памяти или другая ошибка runtime. Если запуск не удался, уменьшите число GPU-слоёв или контекст либо попробуйте CPU.

## Первый сеанс

1. Запустите приложение и настройте runtime по инструкции выше.
2. Выберите модель и дождитесь статуса готовности. Следите за RAM/VRAM.
3. Создайте **Chat** и отправьте простой запрос. Для проверки изображений прикрепите картинку только к модели с поддержкой image input.
4. Для **Agent** выберите проект и начните с небольшой задачи только на чтение, например попросите описать структуру. Перед разрешением изменений или команд проверяйте каждый запрос на подтверждение.

## Частые проблемы

- **Сервер не найден:** проверьте путь или `PATH`, права на исполнение и архитектуру файла.
- **Модель не найдена:** проверьте каталог, имя и целостность GGUF; файлы не скачиваются автоматически.
- **Не хватает памяти или запуск завершился ошибкой:** уменьшите контекст или число GPU-слоёв, отключите MTP или выберите CPU. Максимальный контекст модели не означает, что его можно выделить на конкретном компьютере.
- **Изображение отклонено:** обрабатывать изображения могут только модели с поддерживаемой vision-возможностью и совместимым projector. Настройка Image Processing касается обработки картинки, а не всей языковой модели.
- **GPU не обнаружен:** проверьте сборку llama.cpp с нужным backend и драйвер. Метрики NVIDIA требуют `nvidia-smi`; телеметрия других GPU может быть недоступна.
- **Проблема с пакетом или ярлыком:** запустите приложение из терминала, сохраните точный текст ошибки и проверьте системные зависимости. Настройка Electron sandbox зависит от системы.

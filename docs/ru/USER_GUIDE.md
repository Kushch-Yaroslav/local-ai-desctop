## Интерфейс и чаты

![Главный интерфейс и пустой чат](../img/interface/1-e.png)

В боковой панели расположена история чатов и кнопки создания, выбора, переименования и удаления диалога. Модель, режим, проекты, контекст, рассуждения и веб-доступ задаются отдельно для каждого диалога. Активная задача Agent может продолжаться, пока вы открываете другой чат; панель помечает выполняющийся диалог.

## Панель управления и runtime

![Панель модели, метрик, контекста и Agent](../img/interface/2-e.png)

Выберите модель в верхней панели. Индикатор runtime показывает состояние llama.cpp и поддерживаемый режим ускорения, например MTP. RAM, VRAM, GPU и метрики генерации отображаются при наличии данных; телеметрия NVIDIA зависит от `nvidia-smi`. MTP зависит от модели и runtime, может быть недоступен или выключен.

Переключатель контекста показывает варианты, поддерживаемые моделью и runtime; это не гарантия, что памяти хватит. **Find Maximum Context** подробно описана ниже. Thinking и Reasoning effort влияют на поведение модели, только если она поддерживает эти настройки. Стратегия Agent **Fast/Deep** — отдельный параметр работы агента.

**Chat** предназначен для обычного диалога. **Agent** включает инструменты проектов и другие настроенные инструменты. Настройка **Web: Yes / No** действует для текущего диалога: Yes включает веб-поиск и инструменты чтения страниц, No отключает их. Произвольное управление браузером и отправка форм не предусмотрены. Проверяйте источники и выводы.

### Thinking и глубина рассуждений

Для обычных запросов начните с умеренной глубины. Повышайте её, когда задаче действительно нужен более глубокий анализ; максимальное значение не обязательно улучшает каждый ответ.

<a id="qwen38-xhigh"></a>

### Qwen3.8 и длительное рассуждение xHigh

По наблюдениям автора, Qwen3.8-27B с включённым Thinking и уровнем Reasoning effort xHigh может рассуждать очень долго. Некоторые сложные задачи занимали около часа. Это наблюдение автора, а не бенчмарк и не типичная длительность всех запросов. Долгий этап рассуждений сам по себе не означает, что приложение зависло. Проверяйте, обновляются ли прогресс, активность инструментов и статус runtime. Если прогресса нет или runtime сообщает об ошибке, запуск может зависнуть или завершиться неудачно. xHigh не гарантирует улучшения каждого ответа; для повседневных запросов используйте меньшую или среднюю глубину.

## Проекты и ссылки `@`

![Два проекта и автодополнение ссылок @](../img/interface/3-e.png)

Выберите Project 1 и при необходимости Project 2. Интерфейс поддерживает не более двух корней для удобной работы между проектами. Введите `@`, чтобы выбрать файл или папку в выбранном проекте. Ссылка попадёт в сообщение и получит соответствующий значок проекта.

Например, выберите библиотеку интерфейса как Project 1, а приложение как Project 2. Укажите `@src/Button.tsx` из первого проекта и соответствующую страницу второго, затем попросите Agent сравнить компонент и предложить интеграцию. Перед применением изменений проверьте план, diff и запросы подтверждения.

Можно также явно указать в сообщении абсолютный путь, например `/media/user/another-project`. В режиме Agent допустимые пути из сообщений пользователя добавляются как дополнительные рабочие корни (не более четырёх). Файловые инструменты могут работать с абсолютными путями внутри этих корней. Относительные пути считаются от Project 1 либо, если проект не выбран, от первого явно указанного корня. Фильтр путей отклоняет системные корни, слишком короткие пути и некоторые чувствительные каталоги пользователя. Такой путь не становится Project 1 или Project 2, не появляется в подсказках `@` и не получает значок проекта. Явно указывайте только те каталоги, к которым Agent должен получить доступ.

Терминал запускается в Project 1 или, если проект не выбран, в первом явно указанном корне. Команды терминала могут обращаться к другим расположениям; классификатор блокирует часть команд и запрашивает подтверждение, если безопасность команды нельзя установить. Это не превращает Agent в песочницу. Проверяйте правки и текст команды перед разрешением действий.

## Изображения, вложения и Image Processing

![Выбор CPU или GPU для обработки изображений](../img/interface/7-e.png)

Настройка Image Processing CPU/GPU выбирает устройство для поддерживаемой мультимодальной обработки изображений. GPU может работать быстрее, используя больше VRAM; CPU экономит VRAM, но может быть медленнее. Эта настройка не переключает языковую модель между CPU и GPU. Для картинок нужна совместимая vision-модель и projector.

Можно прикреплять текстовые и программные файлы, PDF, DOCX, XLS/XLSX, CSV/TSV и изображения. Текст извлекается локально; для сканированных PDF может понадобиться OCR, которого пока нет. Табличные данные из CSV и электронных таблиц читаются постранично ограниченными блоками. Проверяйте статус обработки и возможности модели.

## Управление Agent и контекстом

![Рассуждения Agent, код и ход задачи](../img/interface/5-e.png)

![Agent читает файлы, показывает прогресс и подробности контекста](../img/interface/6-e.png)

В таймлайне Agent показываются рассуждения, вызовы инструментов, ход задачи и ожидание. **Pause** — кооперативная пауза: runtime обрабатывает запрос на границе цикла Agent. Она не отменяет уже выполняющийся запрос к модели или вызов инструмента; текущая работа может завершиться до вступления паузы в силу. Затем Agent проходит ограниченный этап сохранения контрольной точки, где доступны только инструменты сохранения состояния, показывает краткий отчёт и завершает этот запуск. Тот же активный запуск не продолжается. Чтобы продолжить, отправьте новое сообщение: оно начнёт новую генерацию, которая сможет использовать сохранённые Task Notes и историю чата. Контрольная точка помогает продолжению, но не гарантирует его.

**Stop** отменяет активную генерацию и выполнение Agent, включая связанные инструменты или терминал там, где это поддерживается. Отмена не является атомарным откатом уже выполненных изменений. Во время Agent также можно отправить текстовое уточнение: runtime может принять его во время генерации и передаст на границе хода модели. В Chat такого же уточнения посреди генерации нет.

**Edit** меняет предыдущее сообщение пользователя, удаляет дальнейшую историю и запускает новую генерацию с изменённого места. **Regenerate** удаляет ветку после выбранного сообщения пользователя и запускает новую генерацию с актуальным состоянием диалога. Ни одна операция не продолжает прежнюю генерацию. Edit и Regenerate недоступны при несовместимом активном запуске; это проверяется интерфейсом и главным процессом.

Индикатор контекста показывает фактический объём prompt, если llama.cpp его сообщает, заданный максимум и остаток. Подробное представление содержит метрики токенов runtime и оценки памяти. Компакция может сохранить полезное состояние, но способна потерять детали и не повышает возможности модели.

## Find Maximum Context

Функция оценивает безопасную границу контекста для выбранной и запущенной модели. Нужен runtime llama.cpp, управляемый приложением, и достаточные данные о выделениях памяти. Приложение несколько раз перезапускает llama.cpp для ограниченного набора проб с KV-кэшем FP16 и Q8, проверяет запуск и состояние, отправляет пробный запрос, собирает данные о памяти и восстанавливает прежнюю конфигурацию. При оценке учитываются доступная память, предполагаемый рост между размерами проб, запас RAM и ограничения VRAM. Перед выбором сохранённый результат сверяется с текущей памятью. Это измерение с ограниченным поиском, а не исчерпывающая проверка до нехватки памяти или абсолютный максимум оборудования.

В качестве практического примера авторской политики: на RTX 3090 с 24 ГБ вне распределения модели/runtime может оставаться около 1,5 ГБ общей VRAM. Если рабочий стол уже использует около 800 МБ, другим задачам может остаться примерно 700 МБ. Значения меняются и не являются фиксированным резервом функции. Код опирается на измеренный запас и настраиваемые проверки, а не на универсальную формулу 1,5 ГБ.

Больший контекст увеличивает нагрузку на память и не обязательно улучшает качество ответа или стабильность системы. Выбирайте размер под задачу с учётом рабочего стола и других процессов.

## Наглядные ответы

![Наглядный ответ: сравнение GPU, карточки KPI и график](../img/interface/4-e.png)

Поддерживаются карточки KPI/метрик, графики Recharts: столбчатые, линейные, с областями, круговые и точечные; сортируемые таблицы, копирование и скачивание CSV, безопасные Mermaid-диаграммы, галереи изображений с источниками и объединённые отчёты. Графики и Mermaid можно экспортировать в SVG. Проверка структуры данных не подтверждает истинность фактов, созданных моделью. Проверяйте источники и значения.
